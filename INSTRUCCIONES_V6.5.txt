REALTIME DATABASE · PASO NUEVO
Para habilitar la sincronización puntual multiusuario:
1. Firebase Console > proyecto agenda-audiovisuales-din.
2. Build > Realtime Database > Crear base de datos.
3. Si Firebase permite usar la base predeterminada de EE. UU., la URL esperada es:
   https://agenda-audiovisuales-din-default-rtdb.firebaseio.com
4. Realtime Database > Reglas.
5. Sustituye las reglas por el contenido de database.rules.json y pulsa PUBLICAR.
6. Si Firebase te muestra una URL de Realtime Database DIFERENTE, abre realtime.js y cambia
   únicamente la constante REALTIME_DATABASE_URL por esa URL exacta.

Si Realtime Database todavía no está creada o su URL no coincide, la agenda NO bloquea el acceso:
seguirá permitiendo reservar y validará empalmes en Firestore, pero mostrará modo eficiente sin
sincronización puntual entre usuarios hasta completar este paso.

PRUEBA MULTIUSUARIO
- Con una sola cuenta debe verse “1 usuario activo”.
- Con dos cuentas activas debe verse “Multiusuario · 2 activos · cambios puntuales”.
- Guarda una reservación con una cuenta.
- La otra debe recibir únicamente el cambio de ese booking, no volver a descargar toda la semana.
- Tras 2 min 30 s sin interacción, la sesión queda inactiva para sincronización puntual.
- Al volver a interactuar, se recuperan solamente las entidades que cambiaron durante la pausa.

CONSUMO
- Abrir/capturar un formulario no escribe en Firestore.
- Una reservación nueva sigue validándose con transacción y hourLocks.
- Presencia y señales ya no consumen lecturas/escrituras de Firestore.
- Cambios remotos disparan getDoc solo del booking o roomBlock afectado.
